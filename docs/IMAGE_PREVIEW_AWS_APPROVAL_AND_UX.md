# AI Dish Visual Preview — Design, Architecture and Organiser Approval
**Team Sprout · Hack the Fork Nigeria 2026 · 19 November 2026**

## What the user sees
For each **eligible, source-referenced** Kitchen Intelligence recipe, show the cookbook recipe beside an optional image preview section. The restaurant owner can pick a presentation style (street food, restaurant, cookbook) and request visual cues ("white plate", "top down", "close up", "wooden board", "banana leaf", etc.). The application deterministically interprets supported presentation/camera phrases without letting the text change ingredients or bypass the kitchen optimiser.

**User journey:** Choose dish → set constraints → select a feasible formulation → read the cookbook trial recipe → specify presentation → inspect the proposed visual prompt → *optionally* generate one conceptual image with an organiser-approved model.

**Every visual:** `AI-generated illustrative concept — actual cooked appearance may differ.`

## Technical architecture
1. `visual_preview.build_preview_draft(recipe, style, restaurant_request)`: validated recipe metadata + permitted visual cues → ≤512-character prompt and bounded negative prompt. Deliberately excludes unlisted ingredient garnish, meat, undocumented yaji and unreviewed peanut topping.
2. The recipe’s underlying calculation engine remains source-of-truth; image AI is **not allowed** to reformulate, add allergens, or change costing.
3. `bedrock_image.TitanImageGenerator`: a replaceable, lazily constructed Bedrock InvokeModel adapter for **Amazon Titan Image Generator V2**. The adapter is present for possible later authorised use, not enabled by the organiser's current model allowlist.
4. `pages/1_Kitchen_Intelligence.py`: generated prompt and constraints are viewable without AWS credentials. A real image button is exposed only if explicit environment gates confirm an approved image model. **No paid call on app rerun or page load.**
5. Generated bytes are validated as PNG/JPEG and shown only for the currently selected recipe+prompt fingerprint. Stored temporarily in Streamlit session only; no uploads to public S3 or Drive, no private image URLs.
6. The image does not claim an experimentally verified finished dish, color, texture or nutrition.

## Organisers' AWS allowlist — verified against the supplied Participant Guide
The official AWS Participant Guide, Section **4. AI Models on Amazon Bedrock**, specifies "Only the models below are enabled in the hackathon accounts. Any other model is denied by the account policy."

- Listed Amazon: Nova Micro, Nova Lite, Nova Pro, Nova 2 Lite, Nova 2 Sonic, Nova Multimodal Embeddings, Titan Embeddings.
- **Not listed:** Titan Image Generator V1 or V2.
- Explicitly *not available*: all Stability AI models, plus other blocked providers.
- **Nova Canvas reached EOL 30 September 2026**; do not use it.
- Therefore **image generation is not currently confirmed or authorised under the existing workshop allowlist**. Do not attempt to access a denied model, bypass policy, buy capacity or deploy a workaround in the hackathon AWS account.

Only after **specific organiser confirmation** that image generation is authorised, an image-capable model is granted to the **team account in us-east-1**, and the quota/free-credit conditions are clear, may the image-generation button be enabled.

## Approval flags — disabled by default
For the *currently implemented Titan V2 adapter* (if the organisers revise the allowlist and grant explicit access), all three settings must be present:

```bash
export ENABLE_BEDROCK_IMAGE_PREVIEW=true
export IMAGE_MODEL_ORGANIZER_APPROVED=true
export BEDROCK_IMAGE_MODEL_ID=amazon.titan-image-generator-v2:0
```

Do not set these based on assumptions or access to an unrelated personal AWS account. The code checks the explicit model ID, mandatory us-east-1 region and the flag, then uses existing AWS SDK credentials. Do not commit access codes or AWS secrets to GitHub.

**Note:** A new authorised model other than Titan V2 would require a new adapter matching its documented request/response format. A text-only or image-understanding model is **not equivalent** to image-generation capability.

## Cost, reliability and safe failure
- No image generated unless the restaurant owner clicks the explicit button and AWS image generation is approved.
- Exactly **one** output image per button click; standard quality and 512×512 size to minimise cost.
- Generated result remains optional; failed inference never breaks recipe output.
- Request text never becomes untrusted raw model instructions: only recognised presentation/camera phrases are included.
- No false claim of cost, taste, protein or ingredient appearance; images not suitable for customer promises or menu selling without approval.
- Titan V2 documented InvokeModel request: `TEXT_IMAGE`, `textToImageParams.text/negativeText`, `imageGenerationConfig`; use `us-east-1` only if actually authorised.
- Ensure licensing and generated-image commercial-use terms are acceptable before public menu release; watermark/provenance information should not be stripped.
- The temporary AWS account may be deleted after ~72 hours, so the production app cannot depend on it for persisted generated images.
